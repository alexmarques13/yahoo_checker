# IPQS Yahoo Device Fingerprint — Logic Summary
# Source: https://s.yimg.com/wm/mbr/js/ipqs-us-east-pixel-0.1.2.js
# Files: ipqs.raw.js (obfuscated) / ipqs.decoded.js (escapes decoded)

## What it is
IPQualityScore device fingerprint SDK, Yahoo-hosted (`ipqs-us-east-pixel-0.1.2.js`).
Obfuscated control-flow + hex/unicode string escapes. Public API is `window.Startup`.

## Public API (window.Startup)
- Init()           start collection + submit (or bind form triggers)
- Pause()/Resume() gate submit until form is ready (Yahoo uses this on password click)
- Store(k,v)       push custom vars into Storage.Variables.dta[]
- AfterResult(cb)  queue success callbacks (Yahoo reads response.request_id)
- AfterFailure(cb) queue failure callbacks
- Finalize(el)     inject hidden inputs into form then submit/click
- FieldStore(k,v)  set Storage.Variables[k]=v
- FixCookies / PruneCookies / AddStorage  cookie helpers
- ProcessStorage() serialize Variables -> application/x-www-form-urlencoded
- Submit()         POST fingerprint payload to IPQS
- FetchExecutionLogs() return Storage.DLG

## High-level flow
1. Yahoo page loads script, sets Startup.Store("sessionId", ipqsSessionId)
2. Startup.Init()
3. Learn.Collect() runs FPItems + ResultItems collectors into Storage.Variables
4. Startup.Prepare() waits until async collectors finish (TotalCompleted >= Waitables)
5. Startup.Submit() POSTs encoded Variables to IPQS learn/fetch endpoint
6. On 200 JSON with request_id:
   - cookie/localStorage device_id_* / device_id saved
   - Storage.Runnable callbacks fired with response
7. Yahoo React wrapper maps response into form fields:
   - iri  = request_id   (MAIN server trust token)
   - irc  = true         (success)
   - irf  = true         (failure)
   - ito  = true         (timeout)
   - ipl  = elapsed ms
   - isl  = true         (script loaded)
8. Form re-submits to Yahoo /password/validate with those fields

## Main trust identifiers
COOKIE (persistent device UDID):
  name: ipqsd
  source: GET https://dtproxy5.yahoo.nc.clients.ipqs.com/udid/udid.json -> {udid}
  TTL: 365 days via Learn.sc("ipqsd", udid, 365)

LOCAL/COOKIE device binding after fingerprint:
  cookie: device_id_{time} = {request_id}-{time}
  localStorage: device_id = {request_id}-{time}
  fallback: fingerprint_{time}

SERVER TRUST ON YAHOO PASSWORD POST (not a cookie):
  form field iri = IPQS response.request_id
  Missing/invalid iri -> challenge/fail eid=3695

## Network endpoints
UDID:
  GET https://dtproxy5.yahoo.nc.clients.ipqs.com/udid/udid.json

Fingerprint submit (primary, random of):
  POST https://dtproxy5.yahoo.nc.clients.ipqs.com/api/*/...long token.../learn/fetch
  POST https://dtproxy6.yahoo.nc.clients.ipqs.com/api/*/.../learn/fetch
  Content-Type: application/x-www-form-urlencoded
  Body: Storage.Variables serialized (dt*, fp*, ipqsd, sessionId, ...)

Retry regions (tries 3-4):
  dtproxy*.yahoo.or.clients.ipqs.com
  dtproxy*.yahoo.eu.clients.ipqs.com

Fallback host (tries > 4):
  fn.nc.ipqualityscore.com

Debug/error:
  GET  fn.nc.ipqualityscore.com/api/error?message=
  POST fn.nc.ipqualityscore.com/api/debug

## Collectors
FPItems (fast path / core):
  ipqsd, fpa..fpv, HLL, HLR, HLO, HLB

ResultItems (full fingerprint set):
  ria..riz, fp*, dpi, fpdt, fpem, fpcs, automation checks, etc.

GFPItems (hash inputs for global fingerprint string):
  dtb..dtaa, dtqq  (screen, colorDepth, pixelRatio, UA pieces, etc.)

Examples of what collectors read:
  - screen / availScreen / colorDepth / devicePixelRatio
  - canvas + webgl vendor/renderer/params
  - fonts list, plugins, touch, fullscreen APIs
  - localStorage / sessionStorage / indexedDB
  - audio devices, timezone, language, platform
  - WebRTC ICE candidates (dtmm)
  - bot/automation markers (webdriver, selenium, phantom, nightmare,
    $cdc_, callPhantom, BrowserAutomationStudio_*, etc.)

## Yahoo password-page integration (React, not in this file)
mode=inject:
  - on submit: Startup.Pause(), then on fingerprint done re-click button
  - AfterResult -> set iri=request_id, irc=true
  - AfterFailure / 10s timeout -> irf or ito, still continue submit
  - without valid iri, Yahoo server fails with eid=3695

## Bottom line
ipqs.js does NOT give Yahoo a simple "trusted cookie" for password login.
It:
  1) keeps device UDID in cookie ipqsd
  2) collects browser signals
  3) POSTs them to IPQS
  4) returns request_id
  5) Yahoo trusts that request_id via form field iri
